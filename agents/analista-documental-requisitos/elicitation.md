# Protocolo de elicitación v0.1

## Objetivo

Obtener información suficiente y verificable para comprender necesidades, procesos, restricciones, reglas y excepciones sin reducir la elicitación a una simple toma de notas.

## 1. Definir objetivo

Antes de elegir técnica, responder:
- ¿Qué desconocemos?
- ¿Por qué importa?
- ¿Quién puede aportar evidencia?
- ¿Qué tipo de evidencia necesitamos?
- ¿Qué decisión o requisito depende de esta información?

## 2. Seleccionar técnica

Elegir según necesidad:

| Necesidad | Técnica preferente |
|---|---|
| Conocimiento profundo o tácito | Entrevista |
| Alinear varios stakeholders | Workshop |
| Ver proceso real | Observación |
| Obtener línea base | Análisis documental |
| Cubrir población amplia | Encuesta |
| Validar interacción o flujo | Prototipo o escenario |
| Entender integraciones | Análisis de interfaces |

La tabla orienta; no reemplaza el juicio.

## 3. Triangular información

Para asuntos materiales, buscar más de una perspectiva o tipo de evidencia cuando sea razonable.

Ejemplos:
- documento + entrevista;
- entrevista + observación;
- observación + workshop.

No exigir múltiples técnicas para tareas triviales.

## 4. Preparar

Registrar:
- objetivo;
- participantes;
- roles;
- temas;
- preguntas iniciales;
- artefactos previos;
- contradicciones conocidas;
- tiempo previsto;
- resultado esperado.

## 5. Ejecutar

Durante la sesión:
- escuchar antes de concluir;
- preguntar por el proceso real;
- explorar excepciones;
- detectar lenguaje vago;
- separar hechos, opiniones y preferencias;
- parafrasear para confirmar;
- no convertir soluciones propuestas en necesidades sin analizarlas;
- registrar contradicciones sin ocultarlas.

## 6. Capturar procedencia

Todo hallazgo relevante debe conservar:
- quién lo aportó;
- fecha;
- sesión;
- contexto;
- tipo de afirmación;
- nivel de confirmación.

## 7. Procesar después

1. ordenar notas/transcripción;
2. clasificar hallazgos;
3. separar as-is y to-be;
4. detectar gaps;
5. detectar contradicciones;
6. generar requisitos candidatos;
7. generar preguntas de seguimiento;
8. preparar resumen de confirmación.

## 8. Confirmar

El stakeholder debe poder:
- confirmar;
- corregir;
- rechazar;
- añadir contexto.

Una respuesta no confirmada sigue siendo evidencia de elicitación, no necesariamente requisito aprobado.

## 9. Iterar

Si quedan huecos:
- elegir siguiente técnica;
- preparar follow-up;
- escalar solo si requiere autoridad o acceso externo.
